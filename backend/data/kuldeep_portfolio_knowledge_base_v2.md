## Nova: Architecture and Tech Stack

<!-- id: project_nova_architecture | type: project | project: nova | topic: architecture -->

A visitor's question goes from a React chat widget on the portfolio (hosted on Vercel) to a FastAPI backend on Render through a POST `/ask` endpoint. The backend embeds the question with Google's `gemini-embedding-001` model, retrieves the top 5 matching knowledge-base chunks from ChromaDB using cosine similarity, and sends those chunks with the question to a Gemini language model, which writes the answer. The sources used are returned with the answer. The knowledge base is a markdown file with one chunk per section, and the index rebuilds automatically at startup whenever the file changes. The stack is Python, FastAPI, ChromaDB, the Google Gemini API (embeddings and generation), Pydantic, slowapi, React, Render and Vercel.

## Nova: Safeguards and Evaluation

<!-- id: project_nova_safeguards_eval | type: project | project: nova | topic: safeguards_evaluation -->

Nova answers only from retrieved context. Its system prompt forbids inventing details, treats retrieved text and visitor input as data rather than instructions, and politely declines off-topic or instruction-override requests. The API has per-IP rate limiting (20 requests per minute by default), a CORS allowlist limited to his portfolio, input length limits, capped conversation history, and error messages that do not expose internals. The Gemini API key stays on the server. Kuldeep also wrote a retrieval evaluation script with a 20-question test set that reports hit@5 and MRR without making LLM calls. No numeric scores are published.

## Nova: Challenges and Design Decisions

<!-- id: project_nova_challenges | type: project | project: nova | topic: challenges -->

Kuldeep Soni made several design decisions while building and deploying Nova on a free hosting tier. Unlike his YouTube RAG project, which uses local Sentence Transformers, Nova uses Gemini embeddings so the backend fits within the 512 MB memory of a free host. Because the free host's disk is wiped on restart, the index is rebuilt automatically at startup, and the collection name includes a hash of the knowledge-base file so edits are picked up on the next deploy. He added rate limiting, CORS restrictions and input limits because the endpoint is public. He also handled the free tier's idle sleep with an offline preview mode in the widget (see the Nova offline preview section).

## Nova: Offline Preview Mode and Cold Starts

<!-- id: nova_offline_preview | type: project | project: nova | topic: offline_preview | status: known_limitation | time_sensitive: true -->

Nova's backend (FastAPI, ChromaDB and Gemini) is hosted on Render's free tier, and a free instance goes to sleep after about 15 minutes without traffic. Waking it takes up to about a minute. While the backend is asleep, the chat widget on the portfolio shows "Offline preview mode" and returns short pre-written answers instead of live retrieval-based responses, so answer accuracy and detail are lower during that time. The widget pings the backend's health endpoint when the page loads to wake it early. Once the backend is awake, Nova answers live from the full knowledge base, so asking the question again after a short wait gives the complete and more accurate answer. This is a limitation of the free hosting tier, not of the system's design, and an always-on instance would remove it. For urgent questions, Kuldeep can be contacted at kuldeepsoni.dev@gmail.com.

## YouTube RAG Agent: Overview

<!-- id: project_youtube_rag_overview | type: project | project: youtube_rag_agent | topic: overview | status: prototype -->

The YouTube RAG Agent is Kuldeep Soni's own GitHub project (https://github.com/justkuldeep/Youtube-RAG). It lets a user ask natural-language questions about a YouTube video's spoken content, instead of watching or scrubbing through a long video to find one answer. The system transcribes the video's audio, splits the transcript into chunks, embeds and stores them, retrieves the most relevant chunks for a question, and passes them to an LLM to generate a grounded answer. It is a working prototype and is not deployed, so there is no live URL.

## YouTube RAG Agent: Pipeline and Tech Stack

<!-- id: project_youtube_rag_pipeline | type: project | project: youtube_rag_agent | topic: architecture -->

The YouTube RAG Agent pipeline has these steps. First, `yt-dlp` extracts audio from a YouTube video. Whisper then transcribes the audio, and `langchain_text_splitters` divides the transcript into chunks. The Sentence Transformers model `all-MiniLM-L6-v2` generates 384-dimensional embeddings, which are stored in ChromaDB. For each question, the system retrieves the top 5 chunks (top_k=5) and gives them to an LLM to produce an answer. A FastAPI `/ask` endpoint serves the question answering, and a frontend with a video/TV-style presentation sits on top. The full stack is Python, yt-dlp, Whisper, LangChain text splitters, Sentence Transformers, ChromaDB, FastAPI, an LLM and a frontend UI.

<!-- id: project_youtube_rag_data_eval | type: project | project: youtube_rag_agent | topic: data_evaluation -->

## SAISA: Roles and Features

<!-- id: project_saisa_features | type: project | project: saisa | topic: features -->

SAISA supports three roles. Students can view their attendance and raise an attendance issue with a reason inside the app, instead of going through informal WhatsApp requests or an in-person meeting with faculty. Faculty and event faculty can submit attendance, including by uploading an Excel file of the enrollment numbers of students who were present, and SAISA can automatically write a message about a student's current, updated attendance status for them. Class coordinators manage the attendance of their own group and can share the attendance details of any particular student directly with that student's parents, so they no longer need to compile Excel files to get updated attendance records. SAISA also provides a separate event attendance module, tracking against a 75% attendance threshold, and attendance reports and summaries.
